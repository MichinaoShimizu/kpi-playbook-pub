指標ページで選んだ指標

指標ページで「選んだ指標に加える」を押した指標です。このブラウザ内にだけ保存され、外部へは送りません。ここで選ぶのは下書きです。重点KPIは、同時に改善の判断をするチームの会議で決めます（複数チームの持ち方）。役割（KPI候補・監視候補など）の読み方は出典と参考値の「バッジの意味」の後半（役割バッジの凡例）、用語は用語（KGI・CSF・KPI）にあります。指標カタログで指標を探す →

    入るのは、重点KPIに選んだ指標の名前・計算式（「02 / 制約とKPI」）と、その指標に本資料が挙げた対の候補・観点（「03 / 測定・目標・合意」）です。いずれも未合意の下書きで、目標値・閾値・測定条件は自チームで決めてから合意してください。すでに書いてある欄は上書きしません。「01 / 目的と成果」とCSFの欄は、この操作では埋まりません。このシートは1チーム分です。

    ほかのチームの分を書くときは、次の順で進めます。

    1. シート末尾の「テキストで保存」で、いまのチームの記入を残す。
    2. 「記入をクリア」で欄を空にする。選んだ指標の一覧は消えません。
    3. 上の一覧で、次のチームの指標の「重点KPIにする」を押す。まだ一覧にないときは、指標ページの「選んだ指標に加える」で先に加える。
    4. 「選んだ指標を空欄に入れる」を押す。

    完成例：AIを使う開発チーム

    記入例・架空 数値・閾値・日程は架空例です。自社の基準値と必要な品質水準で合意してから運用してください。

    目的とKGI
    顧客が待つ改善を利用できるようにする。KGIは事前に対象とした改善IDのうち、対象顧客5社のすべてで利用をイベントまたは顧客確認により確かめた件数。改善IDごとに1件、重複利用は加算しない。利用を確認できない修正は対象外。前期は同条件で1件、今期は3件を目指す。（数値は仮の例）
    対象・期限・成果責任者
    主力サービスの小規模な修正／今期末／事業責任者。実行責任者は開発マネージャー。
    制約とCSF
    実装後の検証・修正で滞留がある。CSFは差し戻しを減らし、検証・修正を円滑に進めるプロセス。検証準備を実装中へ移す施策もあるため、工程間の付け替えで改善に見えないよう、KPIは着手から品質合格までを測る。工程別の待ち・差し戻しでCSFの改善も確認する。
    重点KPIと測定定義
    品質合格までの作業時間。期間内に品質合格した対象作業について、合格時刻−着手時刻の中央値を集計。対象は同程度の小規模修正。指示・検証・修正と待ちを含む。完了件数に加え、期末未完了件数と最長経過日数を併記し、完了分だけで改善と判定しない。中断は別記。
    基準値・目標・判定日
    基準値は直近4週の中央値3日。KGIで追加する2件は検証・修正が提供予定を遅らせていると仮定。提供枠・案内・利用開始の日程から各件は着手後2日以内の品質合格が必要で、差し戻し記録から1日の短縮余地を見込むため、中央値2日を目標案とする。品質と負荷を守り、4週後に実現性と今期末のKGI達成見込みを再確認する。中央値の達成は対象2件の期限内合格を保証しないので、改善IDごとの予定も追う。（数値・日程・根拠は架空例）
    データ源・更新・計測担当
    チケット状態遷移と検証記録／毎週月曜／分析担当。用途・難易度・モデル版を記録。定義v1。
    カウンターメトリクス（ガードレール指標）と停止・再開条件
    修正に費やす工数率＝修正工数÷対象作業の総工数（上限20%）。合格後の重大な不具合（0件）。チームの時間外総工数（上限10時間／週）。時間外総工数または修正に費やす工数率が上限を超えたら拡大停止と既存の依頼量削減、超過が続けば当該施策を停止。重大な不具合なら該当用途の利用を停止。品質条件と負荷の回復を確認し、開発マネージャーが再開を判断。（閾値は仮の例）
    仮説・比較方法・観測期間
    検証手順をAIへの指示と揃えると差し戻しが減り、品質合格が早まる。KGIにつながる条件は、対象改善が予定日に合格し、承認・提供・案内が間に合い、対象顧客5社すべてが今期末までに利用を開始すること。改善IDごとに確認する。時間の短縮率から利用件数を換算しない。同程度の仕事で段階導入し、工程変更と習熟を記録。単純前後比較なら相関として説明する。
    今週の施策・担当・期限
    完了条件と検証手順を揃え、指示テンプレートに反映／開発リーダー／次回定例まで。
    依存関係・必要な支援
    検証環境とレビュー枠の確保をマネージャーに依頼。次回定例までに配分を回答。
    継続・変更・中止の基準
    品質条件を満たし、時間が改善、未完了の滞留も悪化せず、カウンターメトリクス（ガードレール指標）が許容範囲内なら継続。修正に費やす工数率だけで品質を判定しない。時間外総工数または修正に費やす工数率が上限を超えたら拡大停止と既存の依頼量削減、超過が続けば当該施策を停止。重大な不具合なら該当用途の利用を停止。延長する場合は次に確かめる仮説、必要な対象数、追加予算・工数の上限を事業責任者と再合意し、期限までに判断する。
