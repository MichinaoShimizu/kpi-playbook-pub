成果を妨げるところを見つける。

選ぶのは、いまの急所を確かめる数字です。指標の知名度より、自分たちの仕事で起きていることから始めます。

通しの記入例・架空

実装量より、品質合格までの流れを選ぶ

仕事の記録を見ると、検証後の差し戻しが増えていた。CSFは「差し戻しを減らし、検証・修正を円滑に進めるプロセス」。KPI候補は対象作業の品質合格までの時間。修正に費やす工数率・合格後の不具合・担当者の時間外負荷をカウンターメトリクス（ガードレール指標）にする。AI利用状況は参照値とし、KGIへのつながりは仮説として残す。

仕事の流れと、止まっている場所を見る

依頼 → 調査・設計 → 実装 → レビュー・検証 → 提供 → 利用のように、実際の流れを描きます。最近完了した仕事と、まだ終わらない仕事を並べ、待ち時間・離脱・手戻りを確認します。

ツリーとプロセスは、見ているものが違う

ツリーは成果を説明する要素、プロセスは仕事の流れです。ツリーの葉が、そのまま今の制約とは限りません。実際の滞留や失敗を確かめて選びます。

CSF・KPI・施策を別々に書く

CSFは、KGI達成のために、いま最優先で強化するプロセスです。KPIは、そのプロセスの改善を確かめる指標と目標値。施策は、プロセスを変える具体的な行動です。第2章で指標候補を絞り、第3章で測定条件と目標値を合意して、運用するKPIにします。

役割記入例
制約AIで実装は速くなったが、検証と修正で滞留する
CSF差し戻しを減らし、検証・修正を円滑に進めるプロセス
KPI候補と目標案対象作業の着手から品質合格までの経過時間の中央値を、4週後に3日から2日へ（架空の目標案。第3章で根拠と測定条件を合意する）
施策完了条件と検証手順を揃え、AIへの指示にも含める

この例では、検証の準備を実装中へ移す可能性があるため、検証工程だけの時間が短く見えるのを防ぐ目的で、着手から品質合格までを測ります。工程別の待ち・差し戻しの記録で、CSFが改善したかも確認します。全体時間だけでは、どの工程が改善したかは分かりません。

候補を、採用条件で絞る

カタログにはKGI候補・KPI候補と、悪化に気づく監視候補、状況を把握する参照候補の指標のほか、指標ではない枠組み（仕事や指標を整理する考え方）もあります（役割の読み方は指標カタログの「バッジの読み方」）。指標名だけでKGI・KPIは決まりません。例えば継続率は、顧客維持がゴールならKGI、収益拡大に向けて更新プロセスを強化するならKPI候補です。組織の階層を下げるだけではKPIになりません。下の条件で検討します。測りやすい数字だけを残すと、重要な制約から離れます。未計測でも重要なら、計測準備を決めます。

  • 改善するとKGIへ届く理由と、他工程・顧客利用などの成立条件を説明できる
  • 対象チームが改善に関与できる
  • 今の制約に対応する
  • 同じ定義で測る方法がある
  • 移り先（品質・人の負荷・費用・測り方・顧客）の悪化に気づく閾値を置いて打ち手を試せる

その時点で、重点KPIを1つにする

CSFとKPIは固定ではありません。「重点KPIは1つ」とは、その時点で集中する指標を1つにするという意味です。最重要の制約が変わったと確認できたら、四半期末を待たずにCSFを見直し、対応するKPIを選び直します。未達だけを理由に替えず、変更の根拠・判断日・以前の定義を残します。切り替える条件と判断の流れ →

本資料では、同時に改善の判断をするチームごとに、重点KPIを1つ選びます。部門全体の最重要プロセスを先に確認し、各チームの改善がそこを助けるかを揃えます。部門でKGIを共有しても、各チームが同じKPIを追う必要はありません。部門は共通の目的・KGIと、各チームのCSF・重点KPIを一覧化し、運用シートはチームごとに作ります。例えば同じ「顧客への提供」に対し、開発チームは検証の滞留、提供・案内チームは承認待ちを改善します。つながりは仮説として確認し、チームごとのKPIを単純に合算しません。

役割使い方
重点KPI：1つ改善する数字。増やす・減らす方向は指標で決める。
カウンターメトリクス（ガードレール指標）：2〜4個重点KPIの改善が負担を移す先（品質・人の負荷・費用・測り方・顧客）を悪化させていないか確かめる指標。例えば時間外負荷に上限（閾値）を定め、超えたときの停止・再開条件を置く。
参照値：その他四半期の全体確認に加え、制約の変化を調べる際にも使う。
KGI成果へのつながりを、契約周期などに合わせて確認する。

この分け方は本資料の運用方針です。

ここまで決まれば、次へ

  • 制約の根拠を具体的な仕事で示せる
  • CSF、重点KPI、施策を区別できる
  • KPI候補を選んだ理由と、守るものが言える

候補が絞れなければ、仕事のサンプルを調べるか、第1章の対象範囲を狭めます。
