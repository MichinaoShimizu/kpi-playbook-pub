データ・AIの業務品質

データの鮮度

必要な時点までにデータが更新され、利用可能になっているか。

Data Freshness / Timeliness

使い方の例：工程を改善する / KPI候補KGI・KPIの選び分け用語（KGI・CSF・KPI）

この指標に対応するプロセスが、いまのCSFである場合にKPI候補となります。KGIへのつながり、改善できる範囲、測定条件と目標値を合意してから採用します。

定義と測り方

データの更新遅延 = 利用可能の時刻 − 対象イベントの時刻
データの期限遵守率 = 期限内更新数 ÷ 予定更新数

データの利用先ごとに、必要な時点（いつまでにあれば業務が回るか）と更新の予定を先に決め、運用シートに残します。対象イベントの時刻と、利用可能になった時刻の定義（処理が終わった時刻か、利用者が参照できるようになった時刻か）を固定し、時刻の基準（タイムゾーンと、どの系の記録を使うか）を揃えます。予定更新数に、失敗して再実行した回を数えるかを決めます。一部だけ更新した状態で公開した回は、件数を別に残します。

率を使う指標は対象件数を併記し、分母ゼロは未定義、欠損は不明として扱います。期間・対象・除外条件・担当は運用シートに残します。

この項目を使うとき

利用者が必要とする時点までにデータが届いているかを、更新の遅れと期限の守り具合の両方で確かめるとき。速さの指標なので、データの完全性・一意性とデータの妥当性・整合性・正確性を対に置き、間に合わせるために中身を落としていないかと併せて読みます。

採用する前に

遅れを短くすることを目標や評価に結び付けると、届いた分だけで先に公開する、遅れた更新を予定から外す、期限を実績に合わせて後ろへ動かす、で数字だけが良くなります。間に合ったことは、中身がそろっていることも、正しいことも意味しません。夜間・休日の手作業で間に合わせている場合は、担当者の負荷（稼働の健全性）を対で見ます。

KPIの基準値と目標を合意する

目標は、利用先が必要とする時点から決めます（必要のない速さを目標にしません）。遅れは平均だけでなく、遅い側の裾（例えば遅い順に1割の水準）も併せて置き、期限遵守率と両方で見ます。基準値を取る期間は、更新の周期が一巡するまで（本資料の運用案）とします。速さの目標と同時に、完全性・正確性の閾値と、担当者の負荷（稼働の健全性）の閾値を対に置きます。完全性・正確性のいずれかを割ったら公開を止める条件と、負荷の閾値に触れたら締切そのものを見直す条件を、どちらも先に決めます。

カウンターメトリクス（ガードレール指標）

対にする指標の考え方と、閾値の決め方・超えたときに止めるもの

対に置くのは、この指標の数字を良くしようとする行動が、品質・負荷・費用に出す副作用を捉える指標です。数字は、仕事の中身を良くしなくても、負担を別の場所へ移すことで動きます。移した先はこの指標には表れません。下の候補は、その移り先（品質、人の負荷、費用、測り方、顧客）を先に決めて見張るためのものです。この移り先の整理は本資料の運用案で、調査で得た知見ではありません。どこへ移るかはチームが実際に採る行動で変わるため、写す前に自チームの行動から選び直してください（なぜ、その指標が対になるのか）。

対に置く指標は達成目標ではなく、超えたら止める閾値として使います。何から決まる閾値かを先に決めてください。法令・労使協定・社内規程で上限が決まっている項目と、顧客が必要とする水準や予算・資金の制約から決まる項目は、自社の分布からではなく、その上限・要求・制約を根拠にし、上限に達する前に手を打てる水準に置きます（上限そのものを閾値にしません）。自社の分布から決める項目は、基準値とばらつきから置きます（閾値の決め方と停止・再開条件）。

超えたときに止める対象、再開を判断する人、再判定の時期をチームで決め、運用シートに残します。止めるのは閾値に触れさせた施策や進め方で、保守・セキュリティ更新のような投資の区分を止めることではありません。

  • データの完全性・一意性
  • データの妥当性・整合性・正確性
  • 部分更新のまま公開した件数
  • 稼働の健全性
  • パイプライン費用

上の候補からチームで2〜4個を選び、達成目標ではなく超えたら止める閾値として置きます（個数は本資料の運用方針）。対に置くのは、この指標の数字を良くしようとする行動が品質・人の負荷・費用・顧客へ出す副作用と、数え方の変更を捉える指標です。法令・労使協定・社内規程の上限、顧客の要求、予算の制約から決まる項目は、先にそれを確かめます。選ばなかった項目は四半期の確認に回し、観点だけが並ぶ場合は自チームで閾値を置ける指標に具体化してから使います。止めるのは閾値に触れさせた施策や進め方で、止める対象・再開を判断する人・再判定の時期を運用シートに残します。

リンクは、本資料に同じ名前のページがある項目にだけ付いています。近い名前のページは指標カタログで探せます。

時刻・更新予定を固定。速さには完全性と正確性を対にする。

打ち手と確かめ方

遅れの原因を、元データの到着待ち、処理にかかる時間、失敗と再実行、承認待ちに分けて、どこを直すかを決めます。全体を一律に速くするのではなく、必要な時点が早い利用先から順に手を当てます。間に合わないときに一部だけ公開するのか止めるのかの規則は、事前に利用先と合意します。

遅れが縮んだ期に、時刻の定義・更新の予定・対象の利用先が同じかを確認します。一部だけ更新して公開した件数、完全性・正確性の合格率、夜間・休日の対応の回数が同じ期に悪化していないかを併せて見ます。
