重点KPIは1つ。
数字から次の行動へ。

費用・投資・業務効率

運用・保守コストの増減

効率化・自動化・新機能の投入後に、運用・保守にかかる費用と工数が基準期からどれだけ増えたか。削減した工数の裏で増える運用の負担を、同じ期間で対にして見ます。

Run Cost Delta

使い方の例：悪化に気づき、止める / 監視候補KGI・KPIの選び分け用語（KGI・CSF・KPI）

工数削減・自動化・費用効率を重点KPIに置いたときのカウンターメトリクスです。手作業を減らす経路は、基盤・監視・保守の運用へ負担を移すことがあります。削減額だけを見ると、全体では増えている状態を見落とします。削減の効果と同じ期間・同じ対象で増減を並べ、超えたら止める閾値として置きます。

定義と測り方

運用・保守コストの増減 = 当期の運用・保守コスト − 基準期の運用・保守コスト
  • ※運用・保守コストは、対象システムの運用工数（時間 × 単価）＋ 保守・監視・基盤の利用料 ＋ 障害対応の工数を、同じ費目・対象・期間で合計します。

費用明細と工数の分類を、削減の効果を数える対象・期間と同じ範囲に揃えます。共通費の按分方法、含める費目、基準期を判断ログに固定し、変更したら変更日と旧区分での値を残します。

率を使う指標は対象件数を併記し、分母ゼロは未定義、欠損は不明として扱います。期間・対象・除外条件・担当は、最初に一度、判断ログ（結論だけでなく、理由を残す）に残します（週次では書き直しません）。

この項目を使うとき

自動化・効率化・AI活用で削減した工数や費用を重点KPIに置いたとき、その裏で運用・保守の負担が増えていないかを確かめるとき。

採用する前に

金額そのものを下げることを重点KPIにすると、必要な保守・セキュリティ更新・監視を止める行動が有利になります。この指標は削減施策と対で置く閾値であり、費用削減の目標値ではありません。

守る閾値と判断条件を決める

削減施策で見込んだ効果額を上限の出発点にします。増加が効果額を食い潰す水準に触れたら、その進め方を止めて前提を見直します。予算・資金の制約から上限が決まる場合は、そちらを根拠に置きます。

閾値の置き方と、停止・再開条件の決め方は閾値の決め方と停止・再開条件にまとめています。法令・労使協定で決まる上限や、顧客が必要とする水準、予算・資金の制約から決まる閾値は、自社の分布からではなく、その上限・要求・制約を根拠に置きます。

併せて確認する指標・観点

  • AI利用による正味の時間削減
  • SLI / SLO / SLA

費用を抑えた結果、提供している水準が下がっていないかを併せて読みます。

費目を別の予算へ移すと、対象システムの数字だけが下がります。費目の入れ替えがあった期は、入れ替え前の区分でも計算して併記してください。
増加が必ず悪いわけではありません。利用が増えた分の増加と、削減施策の副作用としての増加を分けて読みます。
金額は仮定で動きます。単価・利用量・按分の前提を書き、どの仮定を変えると符号が反転するかを示してください（感度分析の進め方）。
削減した工数は、そのまま現金の利益にはなりません。時間の再配置余力と現金効果を分けて報告します。

打ち手と確かめ方

増加の内訳（利用量の増加、基盤の追加、障害対応、確認作業）を分け、削減施策に由来する分だけを取り出して、対象業務の責任者と扱いを決めます。

単価・利用量・按分の前提を変えて、増減の符号が反転する条件を示します。削減した時間の再配置先と、実際に減った支出を分けて報告します。

根拠と参考情報

定義 本資料の運用案。削減工数を重点KPIに置いたときに対で置く閾値で、業界の標準値ではない。
