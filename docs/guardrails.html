GUARDRAILS / 早見表

カウンターメトリクス早見表

重点KPI（またはKGI）を決めたあと、対に置くカウンターメトリクス（ガードレール指標）を探し直さずに選ぶための一覧です。各指標ページに分かれている対の候補を1枚に集めました。

カウンターメトリクスは、工程を改善する指標（KPI候補）では、その数字を良くしようとする行動が品質・人の負荷・費用・顧客へ出す副作用を捉えます。成果を確かめる指標（KGI候補）では、成果の見え方を良くする行動（対象の絞り込み、判定条件の緩和）と、その成果の裏で増える負担・費用を捉えます。表の3列目は、この読み分けに沿って書いています（用語の説明）。

チームで追う重点KPIは1つ、カウンターメトリクスは2〜4個とします（個数は本資料の運用方針で、業界の標準値ではありません）。この個数はチーム単位の運用で、KGI候補の行は組織・事業の単位で別に確認します。カウンターメトリクスは達成目標ではなく、超えたら止める閾値です。決めるのは、閾値・超えたときに止める対象・再開を判断する人・再判定の時期の4つで、置き方は第3章：閾値の決め方と停止・再開条件、記録先は運用シートです。重点KPIをまだ決めていない場合は第2章：CSF・KPIを選ぶから読んでください。

ここに並ぶ指標は、チーム・システムの改善に使います。個人のランキング・個人目標・人事評価点には使いません（適用範囲。責任者を置くことと個人目標にすることの違いを含みます）。閾値を超えたときに見直すのは、閾値に触れさせた施策や進め方であって、担当者ではありません。

なぜ、その指標が対になるのか

以下は本資料の整理で、調査で得た知見ではありません。自チームで当てはまるかを確かめてから使ってください。

重点KPIを1つに絞ると、その1つを上げる行動が選ばれます。数字は、仕事の中身を良くしなくても、負担を別の場所へ移すことで動きます。移した先はその重点KPIには表れないため、指標だけを見ていると改善に見えます。カウンターメトリクスは、この移り先を先に決めて見張るための指標です。

本資料では、移り先を次の4つに分けて整理しています。かっこ内は本資料で対に置いている指標の例です。表の3列目「対に置く理由」は、指標ごとにどの移り先を見ているかを書いています。この4つで尽きるとは限らないため、当てはまらない移り先があれば自チームで足してください。

  • 品質へ移る。確認・検証・レビューを省くと、その期の速さと量は上がります。省いた分は、差し戻しや変更の失敗として同じ期に出る分と、不具合として後の期に出る分に分かれます（手戻り率と変更失敗率は同じ期、障害流出率は後の期）。
  • 人の負荷へ移る。人数を変えずに前の工程だけを速くすると、レビュー・運用・当番へ待ちと時間外が集まります（稼働の健全性、心理的安全性・持続可能性）。
  • 費用へ移る。手作業を減らした分、基盤・監視・保守の運用と、人が結果を確かめる時間が増えます（運用・保守コストの増減、クラウドコスト効率、AI成功案件あたり総費用）。
  • 顧客へ移る。対象を絞る、判定条件を緩める、案内を省いて先に進ませると、成果は良く見え、解約と問い合わせは後から増えます（継続率・解約率、問い合わせ発生率）。

4つのどこに移るかは、重点KPIではなくその数字を上げるためにチームが実際に採る行動で決まります。同じ指標でも、増員で上げるチームと確認の省略で上げるチームでは、対に置くべき指標が変わります。表の2列目をそのまま写すのではなく、「この数字を来週いちばん早く上げるとしたら何をするか」をチームで挙げ、その行動が何を削るかを見てから選んでください。

対に選べる指標の条件

候補は次の3つで見ます。必須は3だけです。1と2は満たすほうを優先しますが、満たさないことを理由に候補から落とすと、歯止めそのものが残りません。この3つで2〜4個に絞ります。

  1. 先に動く。重点KPIを上げる行動によって、同じ期間のうちに値が動くこと。副作用は遅れて出るものが多いため、遅れて出る指標（障害流出率、解約、費用）は、同じ行動が先に動かす信号（差し戻し、レビューの省略、当番の呼び出し）と組にして置きます。止める判断は先に動く側で行い、遅れて出る側は四半期の答え合わせに使います。
  2. 止められる速さで測れる。止める判断をする会議の周期より短く読めるものを、少なくとも1つ入れること。月次の会計や定期の調査でしか取れない指標（費用、心理的安全性、顧客満足）も対に置けますが、次の締めまで止められません。1回の値だけでは止めず、前後の期と並べて判断します。
  3. 上限・下限で判断できる（必須）。「ここを超えたら止める」と線を書ける信号を持つこと。複数の値を持つ指標（稼働の健全性の残業時間・オンコールの呼び出し回数、SLI / SLO / SLA（サービス水準の指標・目標・合意）の各水準）は、そのうちどれに線を置くかを先に決めます。ただし、法令・労使協定・社内規程で上限が決まっている値は選ぶ対象ではなく、常に線を置きます。選ぶのは、自社の分布から決める線をどこに置くかです。原因を調べるための内訳（工程別・原因別の分解）は、調査の材料であって閾値ではありません。

3を満たさない項目は、対にはせず四半期の全体確認に回します。単に関連するというだけの指標を並べると、閾値の数だけが増え、どれも見なくなります。表の2列目には、閾値を置ける指標のほかに、確かめておく観点が混じります。単位と母集団を書ければ指標、書けなければ観点として扱い、観点は自チームで測れる形に具体化してから使ってください。

目標値ではなく閾値にする理由

対に置く指標へ目標値を与えると、その指標もまた「良くする対象」になり、今度はそちらを上げる行動が別の場所へ負担を移します。歯止めが新しい歪みを生むため、対に置く指標は達成を求めず、超えたら止める線としてだけ使います。何から決まる線かは指標ごとに違います（第3章：閾値の決め方と停止・再開条件）。

線に触れないまま推移すること自体は、成果ではありません。触れなかった期は、重点KPIの改善が実際に進んだかを別に確かめます（第5章：成果を確かめ、見直す）。

重点KPI・KGIの候補と、対にするカウンターメトリクス

使い方の例が「KPI候補」「KGI候補」の50件を、指標カタログと同じ順で並べています。並ぶのは候補で、そのまま採用する一覧ではありません。自チームの工程で副作用がどこに出るかを見て2〜4個を選び、選ばなかった項目は四半期の確認に回します。真ん中の列には、閾値を置ける指標のほかに、確かめておく観点が混じります。単位と母集団を書ければ指標、書けなければ観点として扱い、観点は自チームで測れる形に具体化してから閾値を置いてください。

  • 運用・保守コストの増減

  • 外注費の推移
  • 稼働の健全性
  • 離職率
分母を小さくすれば、成果が増えていなくても上がります。外注への振り替えと、残った人への負荷の集中を見落とします。
継続収益成果を確かめる / KGI候補
  • 解約・減額の金額
  • 粗利益率
  • 一時金と従量課金の扱いを変えた回数
積み上げを急ぐと、値引き・減額と計上の仕方に出ます。数え方を変えた分は、事業の成長と区別が付きません。
粗利益率成果を確かめる / KGI候補
  • SLI / SLO / SLA
  • 顧客満足・推奨度
  • 原価区分を変更した回数
原価を削る行動は、提供水準と顧客の体験に出ます。区分の変え方でも見え方が動きます。
継続率・解約率成果を確かめる / KGI候補
  • 顧客満足・推奨度
  • 問い合わせ発生率
  • 粗利益率
継続は、値引きや解約しにくさでも作れます。残った顧客が満足しているとは限りません。
売上継続率成果を確かめる / KGI候補
  • 拡張を除く売上継続率
  • 顧客数でみた解約率
  • 問い合わせ解決時間・再問い合わせ率
追加購入で解約を覆い隠せます。既存顧客が離れていても、金額では見えません。
機能の採用率成果を確かめる / KGI候補
  • 継続率・解約率
  • 問い合わせ発生率
  • 顧客満足・推奨度
使わせる導線を強めれば上がります。使ったあとに役に立ったかは、この数字では分かりません。
顧客満足・推奨度成果を確かめる / KGI候補
  • 回答率と回答者の構成
  • 継続率・解約率
  • 問い合わせ解決時間・再問い合わせ率
回答者を選べば上がります。答えなかった顧客の不満は数字に出ません。
拡張を除く売上継続率成果を確かめる / KGI候補
  • 顧客数でみた解約率
  • 減額の金額
  • 更新時に値引きした契約の割合
値引きや減額でも契約は残せます。単価を下げて残した契約は、継続として同じには読めません。
初回価値到達率・到達時間工程を改善する / KPI候補
  • 継続率・解約率
  • 問い合わせ発生率
  • 初回体験の品質
  • 初回支援に費やした担当者の時間
到達を急がせる行動は、体験の粗さと人手の支援に出ます。人が付いて到達させた分は、製品の力とは別に見ます。
主要業務の完了率工程を改善する / KPI候補
  • 誤処理・返金の件数
  • 問い合わせ解決時間・再問い合わせ率
  • 開始した試行の総数と除外した試行の割合
完了は、誤りを押し通すことと母集団の除外でも作れます。除外の仕方で割合が動きます。
問い合わせ解決時間・再問い合わせ率工程を改善する / KPI候補
  • 未解決件数と滞留日数
  • 顧客満足・推奨度
  • 稼働の健全性

解決時間を重点に置く場合は、この指標のページにある再問い合わせ率も閾値として対にします。

早く閉じる行動は、未解決の滞留と担当者の負荷に出ます。閉じ方を変えただけの短縮は解決ではありません。
取引流通総額・手数料率成果を確かめる / KGI候補
  • キャンセル・返品の割合
  • 出品者・購入者の継続率
  • 紛争・問い合わせの件数
取引額を伸ばす行動は、キャンセル・返品と当事者の離脱に出ます。成立後に戻った取引も総額には残ります。
デプロイ頻度工程を改善する / KPI候補
  • 変更失敗率
  • デプロイ手戻り率
  • 稼働の健全性

稼働の健全性は、オンコールの呼び出し回数と時間外の対応時間で読みます。

回数を増やす行動は、失敗と手戻り、当番の負荷に出ます。中身のない反映でも件数は増やせます。
変更のリードタイム工程を改善する / KPI候補
  • 変更失敗率
  • デプロイ手戻り率
  • 稼働の健全性

稼働の健全性は、レビューとリリースが集まる工程での時間外の対応時間と呼び出し回数で読みます。

短くする行動は、確認の省略と特定の担当者への集中に出ます。区間の取り方でも短く見せられます。
デプロイ復旧時間工程を改善する / KPI候補
  • 再発率
  • 復旧後の品質
  • 稼働の健全性
早く戻す行動は、暫定対応の積み残しと担当者の消耗に出ます。戻したあとに再発すれば速さの意味がありません。
レビュー応答時間工程を改善する / KPI候補
  • 変更失敗率
  • 稼働の健全性

稼働の健全性は、レビューが集まる工程での時間外の対応時間で読みます。

担当者別に並べません。

早く返す行動は、確認の粗さとレビュー担当への負荷集中に出ます。中身のない返信でも応答にはなります。
スループット工程を改善する / KPI候補
  • 1アイテムあたり所要時間の中央値
  • 手戻り率
  • 変更失敗率
  • 稼働の健全性
件数を増やす行動は、仕事の細分化と手戻りに出ます。1件あたりが小さくなれば件数だけが伸びます。
フロー効率工程を改善する / KPI候補
  • 待ちと実作業の区分の定義を変更した回数
  • WIP・仕掛かり
  • 手戻り率
  • 稼働の健全性
割合は、待ちと実作業の区分の置き方で動きます。同時に多く抱えて実作業に見せることもできます。
WIP・仕掛かり工程を改善する / KPI候補
  • スループット
  • 手戻り率
  • 未完了作業の経過時間
絞りすぎると流れが止まります。着手を止めるだけでは、完了は増えません。
未完了作業の経過時間工程を改善する / KPI候補
  • 修正に費やす工数率
  • 完了とせずに取り下げた件数
  • 未着手のまま滞留している件数
  • 稼働の健全性
滞留は、取り下げや未着手への付け替えでも消せます。数字から消えても仕事は残ります。
修正に費やす工数率工程を改善する / KPI候補
  • 障害流出率
  • 品質合格までの作業時間
  • 稼働の健全性

品質合格までの作業時間はAI関与の作業に限った指標のため、対象を揃えてから使います。

直す時間を減らす行動は、直さずに出すことに出ます。修正が顧客側へ移れば工数率は下がります。
ビルド待ち時間・不安定テスト率工程を改善する / KPI候補
  • 障害流出率
  • テストカバレッジ・自動化率
  • 実行対象から除外したテストの件数
  • CIの実行費用
  • 稼働の健全性
待ちを短くする行動は、検査の除外と実行費用の増加に出ます。外したテストの分だけ待ち時間は縮みます。
社内基盤の自己解決率工程を改善する / KPI候補
  • 未完了の依頼件数
  • 利用チームの満足度
  • 基盤に起因する障害・変更失敗率
  • 稼働の健全性
支援を断れば上がります。利用チーム側で滞った依頼と、基盤に起因する失敗は数字に出ません。
AI業務成功率工程を改善する / KPI候補
  • 評価対象に含めた案件の割合
  • AIの人手修正率・引継ぎ率
  • AIの根拠不一致率・危険応答率
  • 品質判定条件を変更した回数
対象を選び、判定を緩めれば上がります。人が直して通した分も成功に数えられます。
AIの人手修正率・引継ぎ率工程を改善する / KPI候補
  • AI業務成功率
  • AIの根拠不一致率・危険応答率
  • 顧客に届いた誤りの件数
修正を減らす行動は、確認を省いた通過に出ます。直さずに出した誤りは顧客側で見つかります。
AI成功案件あたり総費用工程を改善する / KPI候補
  • AI業務成功率
  • 費用に算入した人の確認時間
  • AIの根拠不一致率・危険応答率
  • 正味の時間削減

正味の時間削減は、現金効果になった分と再配置にとどまる分を分けて読みます。

単価を下げる行動は、品質と人の確認時間への付け替えに出ます。人の確認時間を分子から外せば、その分だけ下がります（この指標の定義では分子に含めます）。
データの完全性・一意性工程を改善する / KPI候補
  • 必須項目と重複判定キーの版を変更した回数
  • 集計から除外した行の割合
  • 母集団の件数
  • 下流の利用者から報告された不整合の件数
合格は、判定の定義と除外で作れます。除外した行の誤りは、下流での不整合として現れることがあります。
データの妥当性・整合性・正確性工程を改善する / KPI候補
  • 検査対象に含めた件数の割合
  • 検査ルールの版を変更した回数
  • 照合元または標本確認で見つかった誤りの件数
検査の対象とルールを緩めれば上がります。検査を通ったことと、現実と合っていることは別です。
データの鮮度工程を改善する / KPI候補
  • データの完全性・一意性
  • データの妥当性・整合性・正確性
  • 部分更新のまま公開した件数
  • 稼働の健全性
  • パイプライン費用
速さを優先する行動は、不完全なままの公開と夜間・休日の対応、費用に出ます。間に合わせた更新の中身は鮮度では分かりません。
MTTD / MTTR / MTBF（平均・全インシデント）工程を改善する / KPI候補
  • インシデント件数・重大度別
  • 同一原因の再発率
  • 顧客からの報告で判明した障害の割合
  • 稼働の健全性

復旧の速さを重点に置く場合は、この指標のページにある検知までの時間（MTTD）も候補に含めます。

平均は、件数の数え方と検知の遅れで良く見えます。気付いていない障害は復旧時間に入りません。
テストカバレッジ・自動化率工程を改善する / KPI候補
  • 障害流出率
  • ビルド待ち時間・不安定テスト率
  • テストの実行時間
割合は、通しやすいテストを足せば上がります。通っていることと、不具合を止められることは別です。
技術的負債の指標工程を改善する / KPI候補
  • 見積の算定条件を変更した回数
  • 解析・検査の対象から除外した範囲
  • 重大脆弱性の期限超過
  • 変更失敗率
見積の条件と対象範囲の置き方で下げられます。検査から外した範囲の負債は数字に出ません。
復旧目標と復旧訓練の達成率工程を改善する / KPI候補
  • 未訓練システム数
  • 訓練シナリオの範囲
  • 実際の障害での復旧時間
  • 稼働の健全性
訓練の範囲を狭めれば達成率は上がります。訓練で満たせても、実際の障害で同じ時間で戻せるとは限りません。
セキュリティ検査の対象網羅率工程を改善する / KPI候補
  • 台帳に載っていなかった資産の発見件数
  • 重大脆弱性の期限超過
  • 検査の除外ルールの件数
台帳と除外ルールで分母を作れます。載っていない資産は網羅率を下げません。
アクセシビリティの未解決課題工程を改善する / KPI候補
  • 確認済み画面の割合と未確認の達成基準数
  • 手動確認の実施件数
  • 利用者から報告された操作できない事象の件数
件数は、確認しなければ増えません。未確認の画面と基準の分だけ、課題が見えていないだけになります。
開発者体験指数工程を改善する / KPI候補
  • 回答率と回答者の構成
  • 質問・尺度・集約方法の版を変更した回数
  • 記録から取れる待ち時間・手戻り率
  • 稼働の健全性
設問と回答者で数字が動きます。回答した人だけの見え方が、開発の実態と離れることがあります。
離職率成果を確かめる / KGI候補
  • 対象人数と離職件数
  • 離職区分ごとの内訳（人数が少ない期は区分を出さず、上位の組織に合算します）
  • 稼働の健全性
  • 心理的安全性・持続可能性
  • 従業員推奨度の回答率
率は、分母の取り方と区分の出し方で見え方が変わります。人数の少ない組織ほど、少数の離職で大きく振れます。
オンボーディング速度工程を改善する / KPI候補
  • 受け入れ担当の支援時間
  • 初期の変更での変更失敗率・手戻り率
  • 入社1年以内の離職

いずれもチームの集計で見ます。

早く立ち上げる行動は、受け入れ側の負担と初期の失敗に出ます。急がせた立ち上がりは、早期の離職として表れることがあります。
機能あたり開発コスト工程を改善する / KPI候補
  • 機能の数え方と原価に含める費目を変更した回数
  • 変更失敗率
  • 障害流出率
  • 技術的負債の指標
  • 稼働の健全性
単価は、機能の数え方と原価に入れる費目で下げられます。安く作った分の失敗と負債は、あとの費用になります。
クラウドコスト効率工程を改善する / KPI候補
  • クラウド費用の実額
  • 分母の定義を変更した回数
  • 応答時間・エラー・処理量・飽和度
  • 稼働の健全性
比率は、分母が伸びれば良くなります。費用そのものが増えていても効率は改善して見えます。
受託案件の採算・納期遵守成果を確かめる / KGI候補
  • 原価見積を改定した回数
  • 受入不具合の件数
  • 検収後の追加対応の工数
  • 稼働の健全性
採算と納期は、見積の改定と品質の先送りでも作れます。検収後に残った対応は案件の外に出ます。
社内業務の自動完結率工程を改善する / KPI候補
  • 対象業務に含めた案件の割合
  • 誤処理率・再処理率
  • 正味の時間削減
  • 稼働の健全性

正味の時間削減は、現金効果になった分と再配置にとどまる分を分けて読みます。

対象業務を選べば上がります。難しい案件を対象から外した分だけ、自動で終わった割合は高くなります。
AI活用率工程を改善する / KPI候補
  • 障害流出率
  • エージェント監督時間比率
  • AI成功案件あたり総費用

人が結果を確かめる時間は所定内にも出るため、稼働の健全性だけでは閾値に触れません。

使った記録は増やせます。使ったかどうかは、成果物の質と手間の代わりになりません。
対象業務での継続活用率工程を改善する / KPI候補
  • 障害流出率
  • エージェント監督時間比率
  • AI成功案件あたり総費用

人が結果を確かめる時間は所定内にも出るため、稼働の健全性だけでは閾値に触れません。

使わせる行動は、成果物の質と確認の手間、費用に出ます。継続して使っていることは、役に立っていることとは別です。
品質合格までの作業時間工程を改善する / KPI候補
  • 修正に費やす工数率
  • 障害流出率
  • 稼働の健全性
速さを優先する行動は、後工程の修正と流出、担当者の負荷に出ます。合格の条件を緩めれば時間は短くなります。
開発エージェントのタスク成功率工程を改善する / KPI候補
  • エージェント監督時間比率
  • エージェント変更の未統合・取り下げ率
  • 障害流出率
  • AI成功案件あたり総費用
任せる範囲と判定の置き方で成功率は作れます。人が見ている時間と、使われずに終わった変更は成功率に出ません。
正味の時間削減成果を確かめる / KGI候補
  • 障害流出率
  • 運用・保守コストの増減
  • 稼働の健全性
  • 削減した時間のうち現金効果になった分（再配置にとどまる分と分けます）
削減した時間は、品質と運用の負担へ移っているだけのことがあります。減った時間がそのまま現金効果になるとも限りません。
AI関与変更のレビュー待ち時間工程を改善する / KPI候補
  • 人のレビュー記録がない変更の割合
  • 障害流出率
  • 稼働の健全性

速さの指標のため、品質と負荷の両方を対に置きます。

待ちを短くする行動は、人の確認を飛ばすことに出ます。記録の残らない変更が増えれば、待ち時間だけが短くなります。

3列目は、左の指標を良くしようとする行動から本資料が導いた説明（論理）で、観測された因果ではありません。自チームで実際にどこへ出るかは、対を置いて確かめてください。

真ん中の列は、各指標ページの「カウンターメトリクス（ガードレール指標）」から、対の候補と、その行の読み方の注記を抜き出したものです。候補の定義・測定条件は候補自身のページに、役割ごとの前置きと指標ごとの注意は左の指標のページの同じ節にあります。監視候補・参照候補・枠組みの指標には、対ではなく併せて確認する項目を各ページに置いています。

リンクが付くのは、本資料に同じ名前のページがある項目だけです。リンクの有無は収録の有無を表しません。名前で引けないときは指標カタログで探してください。
